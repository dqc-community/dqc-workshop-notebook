# DQC Workshop Notebook

[![Open in molab](https://marimo.io/molab-shield.svg)](https://molab.marimo.io/github/dqc-community/dqc-workshop-notebook/blob/main/Tutorial_Notebooks/Marimo_Notebooks/1_Monolithic-vs-Distributed-Tutorial.py) [![Open in Visual Studio Code](https://img.shields.io/badge/Open%20in-VS%20Code-007ACC?logo=visual-studio-code&logoColor=white)](https://open.vscode.dev/dqc-community/dqc-workshop-notebook)

This repository contains materials for the distributed quantum computing (DQC) tutorial workshop. Slides for the workshop are hosted separately at [this URL](https://pitch.com/v/distributed-quantum-computing-cjfvmx).

## Quick Start

Dependencies are bundled with the notebook using [Marimo's sandbox mode](https://docs.marimo.io/guides/package_management/inlining_dependencies/). This means you can run the tutorial directly from GitHub (no clone required!) using the following command:

```bash
uvx marimo edit --sandbox https://github.com/dqc-community/dqc-workshop-notebook/blob/main/Tutorial_Notebooks/Marimo_Notebooks/1_Monolithic-vs-Distributed-Tutorial.py
```

### Clone the Repository

If you want to copy all of the code to your own computer, you can [use `git`](https://git-scm.com/install/) to clone the repo [from the terminal](https://docs.github.com/en/repositories/creating-and-managing-repositories/cloning-a-repository#cloning-a-repository) or [inside VSCode](https://code.visualstudio.com/docs/sourcecontrol/quickstart#_option-a-clone-a-repository-locally).

### Previous Workshops

If you want to access the version of this repo that was used for a previous workshop, check out the [tag list](https://github.com/dqc-community/dqc-workshop-notebook/tags). You can view a specific workshop's notebook directly by specifying the tag in the notebook URL:

```
uvx marimo edit --sandbox https://github.com/dqc-community/dqc-workshop-notebook/blob/<tag-name>/tutorial.py
```

## Requirements

- [uv](https://docs.astral.sh/uv/#installation) (handles installing the correct version of Python and all dependencies)

## Development

For local execution, you can sync dependencies with uv:

```bash
uv sync
```

For development (e.g., access to MCP servers):

```bash
uv sync --extra dev
```

## Run

### Marimo

Run the marimo tutorials (in development mode):

```bash
uv run marimo edit --sandbox Tutorial_Notebooks/Marimo_Notebooks/1_Monolithic-vs-Distributed-Tutorial.py
uv run marimo edit --sandbox Tutorial_Notebooks/Marimo_Notebooks/2_Distributing-a-Circuit-Tutorial.py
```

### Jupyter

For compatibility with the Jupyter ecosystem, we maintain Jupyter notebook versions of the tutorials, generated by marimo using the commands:

```bash
uvx marimo export ipynb Tutorial_Notebooks/Marimo_Notebooks/1_Monolithic-vs-Distributed-Tutorial.py -o Tutorial_Notebooks/Jupyter_Notebooks/1_Monolithic-vs-Distributed-Tutorial.ipynb
uvx marimo export ipynb Tutorial_Notebooks/Marimo_Notebooks/2_Distributing-a-Circuit-Tutorial.py -o Tutorial_Notebooks/Jupyter_Notebooks/2_Distributing-a-Circuit-Tutorial.ipynb
```

Run the Jupyter notebooks:

```bash
uv run jupyter lab Tutorial_Notebooks/Jupyter_Notebooks/1_Monolithic-vs-Distributed-Tutorial.ipynb
uv run jupyter lab Tutorial_Notebooks/Jupyter_Notebooks/2_Distributing-a-Circuit-Tutorial.ipynb
```

If you prefer classic notebook UI:

```bash
uv run jupyter notebook Tutorial_Notebooks/Jupyter_Notebooks/1_Monolithic-vs-Distributed-Tutorial.ipynb
uv run jupyter notebook Tutorial_Notebooks/Jupyter_Notebooks/2_Distributing-a-Circuit-Tutorial.ipynb
```
